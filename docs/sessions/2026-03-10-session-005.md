### Data Model SQLite (v0.1)

- 10 tables (project DB) + 1 table (global DB): problem_versions, datasets, dataset_instances, dataset_compat, solutions, solution_lineage, eval_results, eval_instances, benchmarks, benchmark_solutions, llms
- Normalized metrics (one row per metric, not JSON columns)
- Dual storage: materialized aggregates + raw per-instance data
- Key queries documented (solution info, benchmark comparison, per-instance comparison)
- ID generation: timestamp-based with counter suffix anti-collision
- Migration strategy: sequential version table, forward-only
- Resolved 3 design questions: DM-01 (materialized aggregates), DM-02 (SQLite for LLM registry, not YAML), DM-03 (counter suffix for IDs)
