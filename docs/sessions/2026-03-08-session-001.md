## Key Decisions Made

| Decision | Choice | Rationale |
|---|---|---|
| Persona | Domain expert (optimization) with basic LLM knowledge | Mix of researcher + domain expert profiles |
| V1 environment | Single machine, RTX 5090 32GB VRAM + remote APIs | User's current setup |
| Problem definition | Option A — user provides full OpenEvolve-compatible files | Simplest for V1, no abstraction layer needed |
| Versioning strategy | Immutable snapshots (copy + SHA-256 hash) | Most robust — user can modify working copy freely |
| Dataset management | Format-agnostic, file or dir per instance, train/eval split | Flexible, user's evaluator handles format |
| Dataset compatibility | Declared by user (not enforced) | Balances safety with flexibility |
| LLM credentials | Environment variables | Simple, standard, OpenEvolve-compatible |
| Solution naming | Auto-generated + optional user alias | Best of both worlds |
| Run resume | Supported in V1 via OpenEvolve checkpoints | Important given long runs expected |
| Concurrency | Sequential for local LLM, parallel for remote APIs | Pragmatic V1 compromise |
| Instance injection | Environment variables (REVOLVER_DATASET_DIR, etc.) | Preserves OpenEvolve interface, needs POC |
| Solution storage | Top-N programs (configurable, default 1) | Balance between diversity and storage |
| CLI structure | Single binary with subcommands | Simpler, better discoverability |
| Persistence | SQLite for metrics + YAML for configs | Best balance queryability vs readability |
| Project concept | Project-local `.revolver/` store, global `~/.revolver/` for LLMs | Self-contained projects, no cross-pollution |
| Problem testing | `revolver problem test` command before versioning | Catch bugs early, recommended but not enforced |
| Benchmark stats | mean, min, max, p10, p50, p90, std | V1 aggregate stats, instance-level detail deferred |

## Research Findings

### OpenEvolve + Claude Compatibility
- **Confirmed**: Claude Opus 4.6 works natively via OpenAI-compatible API
- Config: `api_base: https://api.anthropic.com/v1`, avoid setting both `temperature` and `top_p`
- PR #385 fixed Anthropic-specific bugs, example configs merged

### OpenEvolve Problem Definition
- Three files: initial program (any language), evaluator (Python), config (YAML)
- `EVOLVE-BLOCK` markers delimit evolvable code
- Evaluator signature: `evaluate(program_path: str) -> dict`
- `combined_score` is primary fitness metric
- No built-in dataset management — hardcoded in evaluator
- All LLMs must be OpenAI-compatible API
