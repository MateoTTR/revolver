## Summary

Review session on DES-005 and DES-006. User feedback led to a significant architectural decision: introduction of `run` as a first-class entity with `solution` as a lightweight reference. All decisions captured in a refactor changelog document for execution in the next session.

## Work Completed

### DES-005 Feedback & Decisions
- **Evaluator detection priority**: `evaluate()` first, then `evaluate_instance()`, then error. User may write both in the same file.
- **Concurrent run status**: Replace single lock file with `runs/locks/` directory containing per-run lock files.
- **Resume creates new run**: Solves traceability problem — old run and its eval results remain immutable. New run has `resumed_from` reference.
- **Env vars clarification**: `REVOLVER_INSTANCE_LOG` and `REVOLVER_EVAL_LOG` used only by generated wrapper, not by legacy `evaluate()`.
- **Post-run eval on all top-N**: Not just rank-1, all N solutions are evaluated post-run.
- **Rename best.py**: Programs named `rank-N.py` in run directory.
- **RQ-01 (--dry-run)**: Accepted — validates inputs and shows resolved config without launching.
- **RQ-02 (wrapper reuse on resume)**: Accepted — reuse stored wrapper.

### DES-006 Feedback & Decisions
- **Re-evaluation behavior**: Warning + confirmation if results exist, `--force` to skip. Always re-evaluates (does not return cached results).
- **eval results without prior eval**: Clear error with guidance message.
- **Legacy mode aggregation inconsistency**: Accepted risk, documented. Recommend `evaluate_instance()` to avoid.
- **EQ-01 (confirmation)**: Accepted — warning + confirmation + `--force`.
- **EQ-03 (evaluator runner placement)**: `infra/evaluator_runner.py`.

### Major Architectural Decision: Run as First-Class Entity
- **DD-07 revisited**: Re-evaluated top-N design in light of resume semantics.
- **Traceability problem identified**: Resume mutating programs invalidates existing eval results.
- **Solution**: Runs are immutable after completion. Resume creates a new run. Solutions are lightweight DB references to (run_id, rank).
- **New schema**: `runs` table (physical entity with lineage), `solutions` table (logical reference with alias). `solution_lineage` table removed.
- **Storage**: Programs live in `.revolver/runs/<id>/programs/rank-N.py`. No separate `solutions/` directory.
