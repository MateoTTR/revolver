### Task 16: Validation Strategy and Test Plan

Defined a 4-level test strategy:

| Level | Scope | Tools | CI trigger |
|---|---|---|---|
| L0 — Static | ruff lint/format + mypy strict | ruff, mypy | Every push |
| L1 — Unit | Domain + infra layer, mocked | pytest, pytest-cov (>= 80%) | Every push |
| L2 — Integration | 28 CLI commands via CliRunner | pytest, CliRunner | Every push + PR |
| L3 — E2E | Full workflows | pytest + fake LLM server | Nightly / manual |

Key decisions:
- **ruff + mypy** as static analysis gates (strict mode from day one)
- **Coverage targets**: 80% overall, 90% domain, 95% models, 75% infra
- **LLM in CI**: fake OpenAI-compatible server for E2E (no GPU required); mocked at infra boundary for L1/L2
- **Unit tests not documented individually** — managed dynamically during implementation
